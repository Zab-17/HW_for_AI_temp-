## Laptop part (done)
- **Per operator** (FP32, 4 bytes per value):

| # | Operator | Parameters | Storage (bytes) | Multiply-accumulates |
|---|---|---|---|---|
| 0 | CONV_2D (conv1) | 104 | 416 | 36,864 |

| 3 | MAX_POOL_2D | 0 | 0 | 0 (448 comparisons) |
| 4 | RESHAPE | 0 | 0 | 0 (no value computed or moved) |
| 5 | FULLY_CONNECTED (dense1) | 3,600 | 14,400 | 3,584 |
| 6 | FULLY_CONNECTED (dense2) | 68 | 272 | 64 |
| 7 | SOFTMAX | 0 | 0 | 0 (4 exponentials, a sum, 4 divisions) |
| | **Total** | **4,300** | **17,200** | **62,016** |

- **Representative calculations:**
  - conv1: 8 × (4 × 3 × 1) weights + 8 biases = 104 parameters. 3,072 outputs (128 × 3 × 8) × (4 × 3 × 1) = 36,864 multiply-accumulates.
  - dense1: 16 × 224 weights + 16 biases = 3,600 parameters. 16 outputs × 224 = 3,584 multiply-accumulates.
- **Largest storage vs largest work:**
  - dense1 holds 84% of the parameter storage (14,400 bytes), while conv1 does 59% of the multiply-accumulates (36,864).
  - They differ because of weight reuse. Each conv1 weight is used 384 times (once per output position, 128 × 3), each conv2 weight 42 times, and each dense weight once.
  - So storage follows the dense layers and work follows the convolutions.
- **File size vs parameters** (20,772 bytes vs 17,200 bytes of parameters):

| Part | Bytes | Share |
|---|---|---|
| float32 parameters | 17,200 | 82.8% |
| tensor name characters | 1,133 | 5.5% |
| metadata buffers (e.g. minimum runtime version) | 112 | 0.5% |
| RESHAPE target shape | 8 | 0.0% |
| FlatBuffer structure (tables, offsets, shapes, operator list) and alignment padding | 2,319 | 11.2% |

  The 3,572 bytes beyond the parameters are the description of the graph: what each tensor and operator is, how they connect, their names, and padding that keeps buffers aligned.
